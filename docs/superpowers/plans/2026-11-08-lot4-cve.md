# Lot 4: CVEs and Important Bumps Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `tabularium cve <host> [--no-build]` scans three states of a host (deployed, `main`, `main` + nixpkgs update) with vulnxscan, diffs them, lists bumps of important packages, and exports the result.

**Architecture:** Bash orchestrates, as in lots 1–3. Two pure pieces carry the logic and are tested alone: `src/important.nix` (config → important packages) and `src/cve.jq` (two scanned states → one comparison). vulnxscan's CSV is turned into JSON with `mlr`; its log gives the patched CVEs.

**Tech Stack:** Bash (`writeShellApplication`), Nix, jq, miller (`mlr`), vulnxscan (`github:tiiuae/sbomnix`).

**Spec:** `docs/superpowers/specs/2026-11-08-lot4-cve-design.md`

## Global Constraints

- Export: `$TABULARIUM_STORE/<repo>/cve/<host>/<YYYYMMDDTHHMMSSZ>.json` (`TABULARIUM_NOW` overrides the timestamp), written with `write_new`.
- Envelope: in-toto Statement v1, predicate type `https://github.com/gfriloux/tabularium/predicates/cve/v0.1`.
- States: `deployed` (record `subject`), `main` (local `refs/heads/main`), `update` (`main` with the root input named `nixpkgs` overridden to the upstream head of its branch).
- Tiers: `solid` = vulnxscan `sum` ≥ 2; `triage` = 1; `patch` = fixed by a nixpkgs patch (fixed only).
- CVE key in diffs: (vuln_id, package). Kernel = vulnxscan package `linux`: excluded from fixed/new/remaining, counted apart.
- Important packages: `environment.systemPackages`, every home-manager user's `home.packages`, `<ns>.<x>.package` for `ns` in `services`, `programs`, `virtualisation` with `enable = true`, and the kernel.
- Realise by default. `--no-build`: a state that needs a local build is `skipped`, the others are scanned. Before realising, print `<state>: <N> derivations to build` when N > 0.
- A comparison is `degraded` when the two states' source sets differ; `unavailable` when either state is not scanned.
- Exit 0 whenever an export is written (as `freshness`); 1 no record / no `main` / no `flake.lock` on `main`; 64 usage.
- `nix flake check` stays cheap: fake `nix`, fake `vulnxscan`, fake `curl`; real runs by hand. Never assign `$out` in a test. Docs in fish syntax, terse.

## Review Focus

- vulnxscan fails for one state (non-zero exit): that state is `failed` with the reason, the export is still written, comparisons using it are `unavailable`. Test `cve_scan_fails` (Task 4).
- GitHub API unreachable (offline): `update` is `skipped` (`upstream unavailable`), `deployed → main` still computed. Test `cve_offline` (Task 4).
- Lock already at the upstream head: `update` equals `main`; the comparison is computed and empty, no second scan. Test `cve_update_up_to_date` (Task 4).
- A service whose `enable` or `package` throws on evaluation: skipped, the rest of the list survives. Test `important_throws` (Task 1).
- Same CVE on two packages: counted once per package. Test `diff_same_cve_two_packages` (Task 2).

### Task 2: comparison engine (`src/cve.jq`)

**Files:**

- Create: `src/cve.jq`
- Create: `tests/cve-diff.nix`
- Modify: `checks/default.nix`

**Interfaces:**

- Produces: `src/cve.jq`, run as `jq -n --argjson from <state> --argjson to <state> -f cve.jq`, returns a comparison.

State (also what Task 3 writes in the export):

```json
{"status": "scanned", "toplevel": "/nix/store/…", "sources": ["grype", "osv", "vulnix"],
 "cves": [{"id": "CVE-…", "package": "bind", "version": "9.20.29", "severity": "8.1", "sources": ["grype", "vulnix"]}],
 "patched": [{"id": "CVE-…", "package": "unzip"}],
 "important": [{"name": "bind", "version": "9.20.29"}]}
```

`status` is one of `scanned`, `skipped`, `failed` (the latter two add `reason` and carry no `cves`).

Comparison:

```json
{"status": "ok | degraded | unavailable", "missingSources": [],
 "fixed": {"solid": [], "triage": [], "patch": []},
 "new": {"solid": [], "triage": []},
 "remaining": {"solid": [], "triage": []},
 "kernel": {"from": 193, "to": 193},
 "bumps": [{"name": "bind", "from": "9.20.29", "to": "9.20.31"}]}
```

Rules:

- Not both `scanned` → `{"status": "unavailable"}` only.
- `missingSources` = symmetric difference of the two `sources`; non-empty → `degraded`.
- Kernel rows (`package == "linux"`) only counted in `kernel`.
- fixed = in `from`, not in `to`: `patch` if (id, package) is in `to.patched`, else tier by `from`'s source count. new = in `to` only, tier by `to`. remaining = in both, tier by `to`.
- Entries are `{id, package, version, severity}`, sorted by severity (numeric, descending) then id.
- bumps: names in both `important` lists whose version differs, sorted by name.

Each test runs `jq -n --argjson from "$(cat from.json)" --argjson to "$(cat to.json)" -f ${../src/cve.jq}` on inline fixtures and asserts with `jq -e`.

| Test | Setup | Assertion |

| `diff_fixed_new_remaining` | from: A(bind, 2 sources), B(curl, 1), C(git, 1); to: B, D(zlib, 2) | fixed.solid = [A], fixed.triage = [C], new.solid = [D], remaining.triage = [B], status ok |
| `diff_fixed_by_patch` | from: A(openssl, 1); to: no A, `patched` has (A, openssl) | fixed.patch = [A], fixed.triage = [] |

### Task 3: `tabularium cve <host>`, deployed and `main`

**Files:**

- Modify: `flake.nix` (input `sbomnix = { url = "github:tiiuae/sbomnix"; inputs.nixpkgs.follows = "nixpkgs"; }`, runtime `mlr` and `sbomnix.packages.${system}.default` (provides `vulnxscan`), `runtimeEnv` `TABULARIUM_IMPORTANT_NIX`, `TABULARIUM_CVE_JQ`)
- Modify: `tests/lib.nix` (fake `vulnxscan`, fake `nix` extensions, same `runtimeEnv` pointing at the real `src/important.nix` and `src/cve.jq`)
- Modify: `src/tabularium.sh` (usage, `cve`, helpers, dispatcher)
- Create: `tests/cve.nix`
- Modify: `checks/default.nix`

**Interfaces:**

- Consumes: `src/important.nix`, `src/cve.jq` (Tasks 1–2), `latest_record`, `store`, `write_new`, `nixpkgs_inputs`, `gh_api`.
- Produces in `src/tabularium.sh`:
  - `cve_state <name> <installable or path> <no_build>` → prints a state JSON (Task 2's shape) on stdout; never exits non-zero for scan or build problems (they become `skipped`/`failed`).
  - `cve_summary <export file>` → terminal summary.
- Fake `vulnxscan <path> --out <csv>`: copies `$FAKE_VULNX/<basename of path>.csv` to `<csv>`, prints `$FAKE_VULNX/<basename>.log` on stderr, appends `<path>` to `$TMPDIR/vulnxscan.log`; missing fixture → exit 1.
- Fake `nix` additions:
  - `eval --raw <ref>#…toplevel.outPath`: if the ref has `?rev=<sha>` and `$FAKE_NIX_TOPLEVELS/<sha>` exists, print its content (otherwise unchanged behaviour). With `--override-input`, print the content of `$FAKE_NIX_TOPLEVELS/update`.
  - `eval --json <ref>#nixosConfigurations.<host>.config --apply …`: print `$FAKE_NIX_IMPORTANT/<basename of the toplevel the same ref evaluates to>.json`, or `[]`.
  - `build --dry-run …`: print `these $FAKE_NIX_TO_BUILD derivations will be built:` on stderr when that variable is set and > 0.
  - `build --no-link --print-out-paths <installable>`: print the toplevel path that installable evaluates to, and append it to `$TMPDIR/nix-realise.log`.

Flow of `cve`:

1. `<host>` then optional `--no-build`, else usage; `cd` to the top level; newest record (exit 1 as `sbom` if none or invalid); `main` commit and `flake.lock` on it (exit 1 as `freshness`).
2. deployed: the record's `subject` if `nix path-info` succeeds; else the record's commit installable if the record is clean; else `skipped` (`dirty record, toplevel not in the local store`).
3. main: `git+file://$PWD?rev=<main>#nixosConfigurations.<host>.config.system.build.toplevel`.
4. Each state: dry-run → if N > 0 print `<state>: N derivations to build` on stderr, and with `--no-build` → `skipped` (`needs a local build of N derivations`); else realise; `vulnxscan <path> --out <tmp csv> 2><tmp log>`; non-zero → `failed` (`vulnxscan exited <code>`); CSV → JSON with `mlr --icsv --ojson cat`; `sources` = names of the `grype`/`osv`/`vulnix` columns with at least one `1`; `patched` from log lines `<level> <CVE> for '<pkg>' is patched with:`; `important` from the `nix eval --json … --apply` of the same installable (or `[]` when the state is a bare store path).
5. Export: subjects = the scanned toplevels; predicate `{host, repository, generatedAt, mainCommit, states: {deployed, main}, comparisons: {deploy: <cve.jq deployed main>}}`; then `cve_summary`.

Summary layout (one line per comparison, then bumps, then export):

```text
deployed → main: fixed 6 (solid 1, triage 4, patch 1), new 0, remaining 347, kernel 193 → 193
bumps deployed → main:
  bind 9.20.29 → 9.20.31

export: <path>
```

`degraded` appends `[degraded: osv]`; `unavailable` prints `deployed → main: unavailable (<state>: <reason>)`.

### Task 4: the `update` state

**Files:**

- Modify: `src/tabularium.sh` (`cve`)
- Modify: `tests/cve.nix`

**Interfaces:**

- Consumes: `cve_state`, `cve_summary`, `nixpkgs_inputs`, `gh_api` (Task 3, existing).
- Produces: `states.update` (with `nixpkgs: {branch, from, to}`) and `comparisons.update` (`main` → `update`) in the export; a second summary line `main → update: …` and `bumps main → update:`.

Rules:

- The root input named `nixpkgs` from `nixpkgs_inputs <main>`; none, or no branch → `update` `skipped` (`no root nixpkgs input`).
- Upstream head from `gh_api repos/NixOS/nixpkgs/git/matching-refs/heads/<branch>` (same answer shape as in `freshness`); failure → `skipped` (`upstream unavailable`).
- Head == locked rev → `update` is a copy of `main` with `nixpkgs` filled in, no second scan.
- Otherwise the installable is the `main` one plus `--override-input nixpkgs github:NixOS/nixpkgs/<head>`, passed to dry-run, realise and the important eval.
